## 语音识别 online 模式修正（Core Speech Kit）
- 问题：项目已有「边录边识别」实现（RecorderBar.ets 用 AudioCapturer 同时写 WAV + 喂 speechRecognizer.writeAudio），但两处 createEngine 都写死 `online:1`（离线端侧），且 RecorderBar 顶部注释自相矛盾（说"必须用云端 0"却填离线 1）。结果：无离线中文模型的真机上 createEngine 失败、实时识别不启动、只能手填文字。
- 修正：online 官方语义 = `0` 云端在线（精度高/开箱即用/需联网）/`1` 离线端侧（需设备预置中文模型）。
  - RecorderBar.ets：`startRealtimeAsr()` 改为调 `startRealtimeAsrWith(0, true)`，云端失败（allowFallback）再退回 `startRealtimeAsrWith(1, false)`。
  - AsrHelper.ets（文件转文字）：`ensureEngine()` 改调 `createEngineWith(0, true)`，失败退回 `createEngineWith(1, false)`。同步修正了顶部"全程离线"描述、权限注释、以及一处错误的 `recognitionMode:0`→`1` 注释。
- 验证：代码改动已核对（类型/逻辑自洽），完整功能需在 DevEco 真机/联网环境编译验证（本沙箱无 HarmonyOS SDK，未跑 build）。
- 现状缺口：AudioAnswer.ets（"音频作答"大圆钮页）仍只有录音+波形，无实时字幕；如要"录音机那种"体验需把 RecorderBar 的实时 ASR 链路搬过去。

## 重要纠正：Core Speech Kit 仅支持离线（online:1），无云侧（用户核实官方文档 + 日志）
- 用户查证《Core Speech Kit 简介》能力限制表：语音识别「支持的模型类型：离线」；实战文示例 online:1 并注明"目前只支持离线"。结论：online:0 云侧识别在 Core Speech Kit 不存在，AGC 也无"云侧语音识别"服务可开通。此前建议的"云端优先+离线兜底"方向错误。
- 重新核查磁盘代码：RecorderBar.ets / AsrHelper.ets 实际均为 `online:1` 离线，注释已写明"仅支持离线/不支持云侧"，**并未真正写入云侧调用路径**（本条之前那条"已实现云侧优先"的记录有误，以此条为准）。
- 修正残留措辞：RecorderBar.ets 兜底超时段的注释与报错文案原写"云侧未响应/确认网络可用"，与离线前提矛盾，已改为"离线识别运行时未就绪/缺失"等离线准确表述。AsrHelper.ets 无需改。
- 测试机问题（铁证）：日志 `libhiai_ir_infershape.so failed` = 该设备 HiAI 离线推理运行时缺失/损坏 → 离线识别初始化失败，连系统小艺离线识别也跑不起来。属系统/固件/设备镜像问题，非代码、非 AGC。畅享系列（中低端）部分固件/区域版可能未预置离线中文模型或 HiAI 运行时不完整。
- 当前应对：该测试机无法用 Core Speech Kit 自动转写；开发期用 RecorderBar/AsrHelper 已内置的「手动录入文字稿」兜底推进；自动转写真机验证需换离线运行时正常的设备（主流 Mate/P 系列标准 HarmonyOS）。
